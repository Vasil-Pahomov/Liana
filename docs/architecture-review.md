# Liana: функциональное и архитектурное описание, рекомендации по рефакторингу

Дата анализа: 2026-10-31. Анализировалось рабочее дерево ветки `master` (коммит `7014d83`) вместе с незакоммиченными правками (ночной режим на ezTime, переименование `ms` → `millisec`, эндпоинт `/time`).

Сборка `pio run -e nodemcuv2` в этом состоянии проходит успешно: RAM 59,2 % (48 524 из 81 920 байт), Flash 40,9 % (427 527 байт).

---

## 1. Что это

Liana — прошивка для ESP8266/ESP32, которая проигрывает световые эффекты на адресной ленте или гирлянде WS2812 и управляется через web-интерфейс (HTTP + WebSocket), MQTT и, опционально, аппаратную кнопку. Основной сценарий: включили питание, гирлянда сама перебирает эффекты и палитры; при желании открыли страницу в телефоне и переключили вручную или отключили ненужные эффекты из перебора.

## 2. Функциональное описание

### 2.1 Железо и платформы

| Параметр | Значение |
|---|---|
| Контроллеры | ESP8266 (nodemcuv2, d1_mini, esp01s), ESP32 (esp32dev) |
| Вывод на ленту | ESP8266: GPIO2 через UART1 (`NeoEsp8266Uart1800KbpsMethod`); ESP32: GPIO14 через RMT |
| Порядок цветов | RGB, GRB, RBG, RGBW, GRBW, BRG, BGR — выбирается в настройках (`neofeature`) |
| Макс. число светодиодов | 1024 (`MAXLEDS`, статические буферы) |
| Опционально | кнопка вкл/выкл (`SUPPORT_BUTTON`), индикаторный светодиод (`SUPPORT_LED_ON_OFF`) |
| Файловая система | SPIFFS: web-страницы и `config.json` |

### 2.2 Эффекты

Индекс эффекта — это и номер в UI, и значение в WebSocket/MQTT-командах.

| № | Имя в UI | Файл | Поведение | Пересоздаётся при смене палитры |
|---|---|---|---|---|
| 0 | Начальная | `anim_start.cpp` | Белая бегущая точка со шлейфом, затем шумовая заливка. Фиксированные 10 с, затем переход к случайному эффекту | да |
| 1 | Бег | `anim_run.cpp` | Палитра циклически «едет» вдоль ленты со случайной скоростью и направлением | да |
| 2 | Пыльца | `anim_pixiedust.cpp` | Фронт нового цвета проходит по ленте, на границе искрящаяся «пыльца»; поверх — «дыхание» (glow) | да |
| 3 | Вспышки | `anim_sparkr.cpp` | Светодиоды в случайном порядке перекрашиваются в новый цвет со вспышкой; в паузе случайные искры | да |
| 4 | Мерцание | `anim_randcyc.cpp` | Каждый светодиод независимо бежит по палитре со своей фазой | да |
| 5 | Звёзды | `anim_stars.cpp` | Случайные светодиоды плавно загораются и гаснут | нет |
| 6 | Полосы | `anim_spread.cpp` | Цветные пятна расширяются и затухают | нет |
| 7 | Полёт | `anim_fly.cpp` | Частицы с хвостом летят вдоль ленты | нет |
| 8 | Пульс | `anim_pulse.cpp` | Затухающие колебания от случайной точки (табличная функция `PULSE_DATA`) | нет |
| 9 | Статика | `anim_static.cpp` | Градиент палитры по «высоте» (таблица `heightTransTable` для конической ёлки), «дыхание», искры | нет |
| 100 | Магия | `anim_magic.cpp` | Пятна управляются наклоном телефона (deviceorientation), выпад даёт «бум». До 5 одновременных клиентов | нет |
| 101 | OTA | `anim_ota.cpp` | Зелёный прогресс-бар обновления прошивки | нет |
| 255 | Выкл | `anim_off.cpp` | Все светодиоды погашены; автоперебор остановлен | нет |

Общие свойства всех эффектов:

- Один кадр каждые 20–40 мс (период выбирается случайно при смене эффекта).
- Между эффектами 1 с кроссфейда: два буфера `leds1`/`leds2`, новый эффект рисует в один, старый кадр заморожен в другом, `Anim::run()` интерполирует.
- Гамма-коррекция по таблице `BRI` (`brightness.h`, 256 байт в PROGMEM, посчитана в `Brightness.xlsx`), затем умножение на глобальную яркость 0..255.

### 2.3 Палитры

11 палитр (`palette.cpp`): RGB, Rainbow, RainbowStripe, Party, Heat, Fire, IceBlue, XMas, NY, BLR, UA. Палитра — массив опорных цветов, эффекты берут из неё интерполированный цвет по дробному индексу 0..1 (`getPalColor`), циклический вариант (`getPalColorCycle`) или «визуально отличающийся от данного» (`getDifferentColor`).

### 2.4 Автоматический режим

- Каждые 30 с (`INTERVAL`) меняется либо эффект, либо палитра, но не оба сразу. Отключённые пользователем эффекты и палитры в перебор не попадают.
- Пока открыта главная страница, браузер каждые 5 с шлёт команду `I`, которая сдвигает дедлайн, поэтому автосмены не происходит.
- Защита от «отключить всё»: нельзя отключить последний активный эффект или палитру.
- Ночной режим (незакоммиченная правка): с 21:00 до 06:00 по `Europe/Warsaw` принудительно выбираются «Звёзды» и яркость 50; утром конфигурация перечитывается из файла.

### 2.5 Сетевые интерфейсы

**WiFi.** Библиотека PersWiFiManager: при отсутствии сохранённой сети поднимается открытая точка доступа (`WIFI_AP_SSID`) с captive portal (DNS-перехват), страница `wifi.htm` позволяет просканировать и выбрать сеть, запустить WPS, перезагрузить модуль. В сети модуль анонсируется по mDNS как `liana.local`.

**HTTP (порт 80).** Статика раздаётся из SPIFFS, страницы `.htm` прогоняются через шаблонизатор `{{key}}`, где ключ подставляется из query-параметра или из `config.json`. Обработчики:

| Маршрут | Назначение |
|---|---|
| `GET /*` | файл из SPIFFS (с подстановкой шаблонов для `.htm`) |
| `POST /setup` | число светодиодов, яркость, порядок цветов → `config.json`; требуется перезагрузка |
| `POST /mqtt` | параметры MQTT → `config.json` |
| `POST /ota` | «взводит» ArduinoOTA и включает эффект OTA |
| `GET /time` | отладочный вывод текущего времени (незакоммичено) |
| `/wifi/*` | эндпоинты PersWiFiManager (list, connect, ap, wps, rst) |

**WebSocket (порт 81).** Текстовый протокол, одна буква команды + HEX-параметры:

| Направление | Сообщение | Смысл |
|---|---|---|
| клиент → ESP | `I` | запросить состояние; заодно продлевает дедлайн автосмены |
| клиент → ESP | `S` + `AAPP` | выбрать эффект `AA` и палитру `PP` (`FF` в эффекте = выключить) |
| клиент → ESP | `D` + `A|P` + `D|E` + `n` | отключить/включить эффект или палитру `n` в переборе |
| клиент → ESP | `P` + `␠|B` + `CCPP` | «Магия»: позиция `PP`, цвет `CC`, `B` = «бум» |
| ESP → клиент | `I` + `AAPPDDDDPPPP` | состояние: эффект, палитра, маски отключённых эффектов и палитр |

**MQTT.** Только клиент, подписка на один топик. Команды в теле сообщения: `on`, `off`, `palette=n`, `animation=n`, `duration=сек`, `brightness=n`, `brightness up`, `brightness down`. Переподключение раз в 10 с.

**OTA.** ArduinoOTA на порту 8266 с паролем. Слушатель запускается только после нажатия кнопки OTA в web-интерфейсе (`otaBegin`), на ленте показывается прогресс. В `platformio.ini` есть `*_ota` окружения для `espota`.

### 2.6 Конфигурация

`/config.json` в SPIFFS: `leds`, `brightness`, `neofeature`, `disabledAnims`, `disabledPals` (битовые маски), `mqttHost`, `mqttPort`, `mqttClientId`, `mqttLogin`, `mqttPass`, `mqttTopic`. При чтении значения вне диапазона заменяются на умолчания. Сохраняется из web-форм и при переключении отключённых эффектов/палитр.

## 3. Архитектура

### 3.1 Модули

### 3.2 Зависимости между модулями

```
Liana.cpp ──► anim ──► palette ──► color
   │           │  └──► NeoPixelWrapper ──► NeoPixelBus
   │           └──► config, hw_led
   ├──► wifi ──► web ──► config, ota, (ezTime: tz, currTm из Liana.cpp)
   │       └──► websocket ──► anim, config, (millisec из Liana.cpp)
   ├──► mqtt ──► anim, config
   ├──► ota ──► anim
   └──► hw_button ──► anim, config

Обратные связи через extern: anim.cpp и websocket.cpp пишут в millisec (Liana.cpp);
web.cpp читает tz/currTm (Liana.cpp); Liana.cpp напрямую правит animInd/paletteInd (anim.cpp).
```

Граф в целом слоистый (приложение → сервисы → движок эффектов → драйвер), но три переменные (`animInd`, `paletteInd`, `millisec`) и объект `currentConfig` читаются и пишутся из пяти модулей напрямую. Автор это знает: в коде три комментария `TODO: it's bad thing to reference that var here`.

### 3.3 Поток выполнения

Кооперативный суперцикл без RTOS-задач (на ESP32 тоже всё в loop-таске Arduino).

```
setup():
  Serial, SPIFFS, configLoad
  wifiSetUp  → persWM.begin (неблокирующий), MDNS, webSetup, wsSetup
  mqttSetup
  tz.setLocation("Europe/Warsaw")        ← до подключения WiFi
  anim.setAnim(0); setPeriod; setPalette; doSetUp (configLoad ещё раз, new NeoPixelWrapper, Begin)
  otaSetUp, ledSetUp, buttonsSetUp

loop():
  anim.run()                              ← кадр, если прошёл период
  if millis() > millisec и не выключено:  ← автоперебор + ночной режим
      выбрать: сменить эффект или палитру
      ...
  wifiLoop  → persWM.handleWiFi, webServer.handleClient, webSocket.loop, dnsServer
  mqttRun, otaLoop, events() [ezTime], buttonsLoop
```

### 3.4 Конвейер кадра

```
runImpl() пишет Color в leds[] (логический RGB 0..255)
   │
   ▼
Anim::run(): если идёт переход — interpolate(leds[i], leds_prev[i], t)
   │
   ▼
BRI[c] (гамма из PROGMEM) × brightness / 256   для каждого канала
   │
   ▼
NeoPixelWrapper::SetPixelColor → NeoPixelBus<Feature, Method>::SetPixelColor
   │
   ▼
strip->Show()  (UART1 на ESP8266 / RMT на ESP32)
```

Эффекты не знают о переходах, гамме и яркости — это хорошее разделение. Все эффекты пишут только в `leds[]`, а служебные буферы `ledstmp[]` и `seq[]` используют как «scratch» со своей семантикой в каждом эффекте.

### 3.5 Модель эффекта

`Anim` — один класс, в котором каждый эффект представлен парой методов `animXxx_SetUp`/`animXxx_Run`, а выбор — через указатели на члены `setUpImpl`/`runImpl` в `switch (animInd)`. Состояние эффекта хранится в общих полях `phase`, `pos`, `inc`, `curColor`, `prevColor`, `seq[]`, `ledstmp[]`, смысл которых в каждом эффекте свой (в `anim_stars` `seq` — фаза звезды, в `anim_pulse` — фаза пульса, в `anim_sparkr` — перестановка индексов). Фактически это стратегия, реализованная руками, без интерфейса.

### 3.6 Память (ESP8266)

| Что | Размер |
|---|---|
| `leds1`, `leds2`, `ledstmp` (3 × 1024 × 3 байта) | 9 216 байт |
| `seq` (1024 × int) | 4 096 байт |
| `DynamicJsonDocument` конфигурации | 1 024 байта (куча) |
| Буферы NeoPixelBus | 3 × N байт + буфер метода |
| Итого статика по отчёту линкера | 48,5 КБ из 80 КБ |

Статические буферы под 1024 светодиода занимают 13 КБ независимо от реального числа светодиодов (обычно 50–300). При 59 % занятой RAM до старта WiFi-стека это главный кандидат на экономию. Сам `config.h` содержит TODO об этом.

## 4. Найденные проблемы

Отсортированы по важности. Всё ниже установлено чтением кода; что проверено сборкой, отмечено отдельно.

### 4.1 Ошибки

1. **Выход за границы массива палитр по MQTT.** `setPalette(int paletteIndex)` в `anim.cpp:217` проверяет диапазон у глобальной `paletteInd`, а не у аргумента. Команда `palette=99` или `palette=-1` проходит, `pals[palind]` читает мусор, следующий кадр разыменовывает невалидный указатель. Исправление однострочное.

2. **Переполнение `millis()` через 49,7 дня.** Сравнение `millis() > millisec` в `Liana.cpp:86` с `millisec = millis() + INTERVAL`. В последние 30 с перед переполнением `millisec` уже «перевернулся» в маленькое число, и условие истинно на каждой итерации: эффект и палитра меняются тысячи раз в секунду, с рассылкой `wsNotify` и Serial-спамом, пока `millis()` не обнулится. Для гирлянды, которая висит весь сезон, это реальный сценарий. Правильная форма: `(long)(millis() - millisec) >= 0`. Аналогичная конструкция в `Anim::run()` даёт лишь короткий всплеск кадров, но её стоит поправить тем же хелпером.

3. **Подсчёт включённых эффектов не видит эффекты 8 и 9.** `getEnabledAnimsCount()` считает нулевые биты среди `ANIMS-1 = 8` младших, то есть индексы 0..7. «Пульс» и «Статика» не учитываются ни в защите от отключения последнего эффекта, ни в решении `changeAnim`. Пример: отключены 1..7, активны 0, 8, 9 — счётчик вернёт 1, автоперебор остановится, отключить 8 или 9 будет нельзя. Там же: `setAnimation()` отвергает индекс 9 (`animIndex >= ANIMS`), поэтому по MQTT «Статику» выбрать нельзя. Корень — `ANIMS` означает «число перебираемых» (1..9), а используется и как «число всех».

4. **`memset(seq, 0, ledsNum)` в `anim_spread.cpp`** обнуляет `ledsNum` байт, а не элементов `int`: очищается только четверть массива, остальные элементы хранят значения предыдущего эффекта (например 255 от «Звёзд»). Видимого вреда почти нет (ширина получается отрицательной и ничего не рисуется), но это следствие коммита `33d7852`, где `seq` сменил тип с `byte` на `int`.

5. **`rng()` вместо `rngb()` в `anim_pixiedust.cpp:9`.** `(float)rng()/256` — число порядка миллионов, `getPalColor` для аргумента ≥ 1 всегда возвращает последний цвет палитры. Первый цвет «Пыльцы» никогда не случайный.

6. **`hw_button.cpp`: `_toggleOnOff()` вызывается до объявления.** Прототипа нет ни в `.h`, ни выше по файлу. Подтверждено сборкой с `-DSUPPORT_BUTTON=1`: `error: '_toggleOnOff' was not declared in this scope` в `hw_button.cpp:28`. То есть функция кнопки, влитая в `master` из PR #47, в текущем виде не компилируется.

7. **`NeoPixelWrapper::cleanup()` для BGR удаляет `_pBrg`** вместо `_pBgr`, а `_pBgr` не инициализируется в конструкторе. Проявится только при повторном `Begin()`, которого сейчас нет, но это мина.

8. **Ночной режим: `tz.setLocation()` вызывается до подключения WiFi.** ezTime при `setLocation` ходит в сеть за правилом зоны; `persWM.begin()` неблокирующий, соединения в этот момент нет, запрос проваливается, зона остаётся UTC. Это и есть причина TODO «it's UTC for some reason». Варианты: `tz.setPosix(F("CET-1CEST,M3.5.0,M10.5.0/3"))` без сети вообще, либо вызывать `setLocation` в колбэке `persWM.onConnect`.

9. **Опечатка `disableddPals` в `data/config.json`.** Безвредна (умолчание 0), но показывает отсутствие валидации схемы.

### 4.2 Нет проверки входных данных

- `wsSet`: индекс эффекта из сети не проверяется (попадает в `default` → выключение, но затем автоперебор сразу включит случайный эффект).
- `wsSetDisabled`: `1 << ind` при `ind ≥ 32` — неопределённое поведение.
- `webOnSetup`: значения формы пишутся в файл без проверки, валидируются только при следующей загрузке.
- `wsPoint`: номер соединения используется как индекс в `amdata[5]`; совпадает с лимитом клиентов библиотеки WebSockets, но связь неявная.

### 4.3 Безопасность (для локальной сети, но стоит знать)

- `GET /config.json` отдаёт файл конфигурации вместе с паролем MQTT любому в сети.
- Пароль MQTT печатается в Serial при каждой попытке подключения.
- Пароль OTA захардкожен в `ota.h` и `platformio.ini` и лежит в публичном репозитории.
- Точка доступа настройки без пароля.
- `indexKeyProcessor` подставляет query-параметры в HTML без экранирования (`/?restartmsg=...`) — отражённый XSS; параметр `alt` — открытый редирект.

### 4.4 Структурные проблемы

- **Глобальное состояние и обратные зависимости.** `animInd`, `paletteInd`, `millisec` правятся из `Liana.cpp`, `anim.cpp`, `websocket.cpp`, `mqtt.cpp`, `ota.cpp`, `hw_button.cpp`. Логика «что происходит при смене эффекта» размазана: `setAnimation()` ставит дедлайн, `wsSet` его не ставит, `wsInfo` продлевает, `loop()` переставляет.
- **Реестр эффектов продублирован в четырёх местах:** `switch` в `Anim::setAnim`, константа `ANIMS`, радиокнопки в `index.htm`, описание команд в README. Палитры — в трёх: `pals[]`, `PALS`, градиенты в `index.htm`. Добавление эффекта требует синхронных правок везде.
- **Магические числа:** 0/255/100/101 как индексы специальных эффектов, 10000 мс для стартового эффекта (в двух файлах), 5 — «Звёзды» ночью, 50 — яркость-маркер ночного режима (`if (brightness == 50) configLoad()` перечитывает SPIFFS и JSON в цикле).
- **`loop()` смешивает** планирование, ночной режим, логирование и условную компиляцию (`USE_START_ANIMATION`, `USE_STATIC_BRB_AFTER_START`); ветвление `changeAnim`/`changePal` трудно прочитать.
- **Эффекты делят scratch-поля** с разной семантикой; добавить поле для одного эффекта нельзя без изменения `Anim`.
- **`#include "NeoPixelWrapper.cpp"`** — `.cpp` подключается как заголовок и одновременно компилируется как отдельная единица трансляции.
- **Лишняя зависимость:** `anim_magic.cpp` подключает `<SoftwareSerial.h>`, который нигде не используется; из-за него в `platformio.ini` висит `EspSoftwareSerial`.
- **Заголовки зависят от порядка включения:** `web.h` использует `ESP8266WebServer` без включения; имена `wifi.h`, `color.h`, `palette.h`, `mqtt.h` слишком общие (на регистронезависимой ФС `wifi.h` соседствует с `<WiFi.h>`).
- **Конфигурация компиляции в `config.h`** (`SUPPORT_BUTTON`, пины, SSID) вместо `build_flags`, поэтому локальные правки под конкретное устройство (сейчас в diff: `"Liana Long"`, IP для OTA) попадают в отслеживаемые файлы.
- **Нет автоматических тестов.** `tests.cpp` — ручной вывод в Serial. Чистая логика (`Color`, `Palette`, маски, планировщик) тестируется на хосте, но `Color::println` и `rng()` тянут Arduino.
- **UI:** весь JS inline в `index.htm`; `setup/mqtt/ota.htm` копируют один и тот же `start()`, который на двух страницах падает на отсутствующем `#neofeature`; в `index.htm` мёртвая ссылка `<link rel="script" href="main.js">`; форма MQTT показывает пароль открытым текстом.
- **Устаревшие зависимости:** SPIFFS объявлен deprecated в ядре ESP8266 (рекомендован LittleFS), ArduinoJson 6 (актуальна 7, `DynamicJsonDocument` там удалён).
- `Brightness.xlsx` — бинарный «исходник» таблицы в репозитории.

### 4.5 Незакоммиченные изменения

Текущий diff смешивает четыре независимых вещи: переименование `ms` → `millisec`, ночной режим с ezTime, отладочный `/time`, и локальные настройки (`"Liana Long"`, IP `192.168.0.31`). Первые две заслуживают отдельных коммитов, последние две в `master` не нужны.

## 5. Рекомендации по рефакторингу

Порядок выбран так, чтобы каждый этап был самостоятелен и проверяем на железе, а поведение для пользователя не менялось до этапа 3.

### Этап 0. Точечные исправления (без изменения архитектуры)

1. `setPalette`: проверять `paletteIndex`.
2. Хелпер времени и замена всех `millis() > deadline`:
   ```cpp
   inline bool timeReached(unsigned long deadline) { return (long)(millis() - deadline) >= 0; }
   ```
3. Разделить понятия: `ANIM_COUNT` (все обычные эффекты, 0..9) и диапазон перебора (1..9). `getEnabledAnimsCount` считает `ANIM_COUNT` бит, `setAnimation` принимает `< ANIM_COUNT`, плюс 100 и 255 явно.
4. `memset(seq, 0, ledsNum * sizeof(seq[0]))`; `rngb()` в `anim_pixiedust`; `_pBgr` в конструкторе и `cleanup`; прототип `_toggleOnOff` (или `static` выше `buttonsLoop`).
5. Убрать `#include <SoftwareSerial.h>` и зависимость `EspSoftwareSerial`.
6. Ночной режим: `setPosix` вместо `setLocation` (или `setLocation` в `onConnect`); параметры (включён ли, часы, эффект, яркость) в конфиг; вместо маркера `brightness == 50` — явный флаг `nightActive` и поле `dayBrightness`.
7. Проверка диапазонов в `wsSet`, `wsSetDisabled`, `webOnSetup`; экранирование в `indexKeyProcessor`; не отдавать `/config.json` по HTTP (проверка пути в `webFileRead`); убрать пароль из Serial.
8. Починить `config.json`, убрать мёртвый `<link>`, вынести `start()` только в `setup.htm`.

### Этап 1. Собрать состояние в один объект: `Player`

Цель: убрать `extern animInd/paletteInd/millisec` и дублирование логики смены.

```cpp
class Player {
public:
  void begin(Config&, Anim&);
  void tick();                       // то, что сейчас в loop(): автоперебор, ночной режим
  void select(int anim, int pal);    // из web/ws/mqtt/button
  void turnOff(); void turnOn();
  void holdFor(unsigned long ms);    // "duration=", "I" из браузера
  void setBrightness(int);
  State state() const;               // anim, pal, маски — для wsNotify и /api/state
  void onChange(std::function<void(const State&)>);  // подписка websocket
private:
  int animInd_, palInd_; unsigned long deadline_; bool nightActive_; int dayBrightness_;
  void pickNext();                   // «либо эффект, либо палитра», с учётом масок
};
```

`loop()` сводится к `anim.run(); player.tick(); wifiLoop(); ...`. `websocket.cpp`, `mqtt.cpp`, `ota.cpp`, `hw_button.cpp` вызывают методы `Player` и ничего не знают о дедлайнах. Условная компиляция `USE_START_ANIMATION`/`USE_STATIC_BRB_AFTER_START` либо становится настройками, либо удаляется (обе выключены).

### Этап 2. Эффекты как классы и единый реестр

```cpp
struct FrameContext {            // то, что сейчас — поля Anim
  Color* leds; int ledsNum; const Palette* palette;
  Color* tmp; int* seq;          // общие scratch-буферы, чтобы не плодить RAM
  const byte* heightTable;
};

class Effect {
public:
  virtual void setUp(FrameContext&) = 0;
  virtual void run(FrameContext&) = 0;
  virtual bool restartOnPaletteChange() const { return false; }
  virtual ~Effect() = default;
};

struct EffectInfo { uint8_t id; const char* name; Effect* effect; bool cyclable; };
extern const EffectInfo EFFECTS[];  // единственный источник: id, имя, перебираемость
```

Каждый эффект хранит собственные поля (`phase`, `inc`, `curColor`) у себя, а не в общих `Anim::phase/pos/inc`. `Anim` остаётся владельцем буферов, переходов, гаммы и яркости, но вместо `switch` берёт `Effect*` из реестра. Аналогично палитры: `struct PaletteInfo { const char* name; const Palette* pal; }`. Количества выводятся из размера массивов, константы `ANIMS`/`PALS` исчезают. Виртуальные вызовы раз в 20 мс на ESP8266 ничего не стоят.

### Этап 3. Один источник правды для UI

- `GET /api/catalog` → JSON со списком эффектов и палитр (id, имя, опорные цвета палитры), `GET /api/state`. `index.htm` строит кнопки и градиенты из каталога. Исчезают ручные правки HTML при добавлении эффекта.
- WebSocket-протокол можно оставить текстовым (он компактен и работает), но стоит перейти на JSON-сообщения, чтобы расширять без разбора позиций символов.
- JS вынести в `main.js`, страницы отдавать gzip (раскомментированная ветка в `webFileRead`).
- Класс конфигурации заменить на `struct Settings` с явными умолчаниями и методом `validate()`; хранить только значения, не `DynamicJsonDocument`; перейти на ArduinoJson 7.

### Этап 4. Платформа и гигиена

- **LittleFS вместо SPIFFS** на обеих платформах. Это меняет образ ФС и инструкцию прошивки из README (адрес `0x100000`), поэтому делать отдельным релизом с заметкой для пользователей.
- **Динамические буферы:** один `malloc` на `ledsNum` при инициализации вместо `MAXLEDS` статики. Освобождает до ~13 КБ RAM при типичной гирлянде.
- **`platformio.ini`:** фичи (`-DSUPPORT_BUTTON`, пины, SSID) через `build_flags`; OTA-пароль и IP в `extra_configs = platformio_local.ini` (в `.gitignore`); `framework = arduino` только в `[env]`. Добавить GitHub Actions с матрицей сборок и `pio check` (cppcheck/clang-tidy уже прописаны, но не запускаются).
- **Тесты на хосте:** окружение `[env:native]` и `test/` с Unity для `Color`, `Palette`, масок конфигурации и `Player::pickNext` (после этапа 1). Для этого убрать `Serial` из `color.h` и пробросить генератор случайных чисел через параметр.
- Переименовать общие заголовки (`liana_wifi.h`, `liana_color.h` или пространство имён `liana`), заменить `Brightness.xlsx` на скрипт-генератор таблицы, убрать включение `.cpp`.
- SSID точки доступа формировать из chip ID (`Liana-XXXX`), чтобы несколько устройств не конфликтовали и не требовали правки константы.

### Что не трогать

Математика эффектов, двухбуферный кроссфейд, гамма-таблица, выбор NeoPixelBus и его методов вывода — всё это работает и не мешает рефакторингу. Этапы 1–2 меняют только то, кто владеет состоянием и как выбирается эффект; визуальный результат должен остаться побайтно тем же, что удобно проверять на ленте.
